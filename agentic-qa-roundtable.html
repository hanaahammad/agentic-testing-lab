Two ways to put an AI agent into testing, and how they fit together

The testing team connects an agent to Jira and uses a skill that turns user stories into test cases. The Data and AI lab built an agent that writes, runs and triages the tests and files the bugs. This page lines them up, proposes a combined workflow, and collects everyone's view on the open decisions.

Strengths of the team's approach

  • Works where the team already works: stories and test cases stay in Jira.
  • The skill encodes the team's own way of writing test cases, so results are consistent.
  • Fast to adopt: no new repository or pipeline needed to start.

Strengths of the lab's approach

  • Goes past design: scripts are written, run in CI and kept as a regression suite.
  • Triage separates real bugs from broken tests and environment problems before anything is filed.
  • Closes the loop: a fix is confirmed by a re-run, and the issue closes itself.

The only change to the lab is its tracker module: it would read approved cases from Jira and file bugs into Jira, through the same connector the team already uses, instead of GitHub Issues.
